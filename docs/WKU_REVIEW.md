# Проверка профилей ЗКУ, 26.09.2026

## Вывод

Пресеты проекта нельзя выдавать за утверждённые требования ЗКУ имени
Махамбета Утемисова. В исходном YAML курсовой прямо указано, что параметры
взяты из общих представлений об оформлении. Единой подтверждённой методички
для всех четырёх типов работ и всех кафедр в ходе проверки не установлено.

## Официальные материалы

  Содержит порядок обучения, аттестации и академической честности; не подтверждает
  весь набор числовых параметров оформления в наших YAML.
- [Правила оценки учебных достижений](https://wku.edu.kz/images/2022/8ru.pdf).
  Критерии связываются с результатами обучения и силлабусом. Опубликованная
  рубрика диплома включает оформление и презентацию. Проверка DOCX не измеряет
  защиту работы и не может воспроизводить итоговую оценку комиссии.
- [Архивный учебный материал «Современные технологии обучения»](https://library.wku.edu.kz/index.php?Itemid=2&gid=7717&lang=kz&option=com_docman&task=doc_download).
  По поисковому индексу встречаются 14 пт, поля 30/10 мм и оглавление.
  Полный файл недоступен при открытии; это частичное архивное свидетельство,
  а не основание объявлять требования действующими для всего университета.

## Сопоставление

| Параметр | Пресеты | Решение |
|---|---|---|
| Шрифт, поля, интервалы | Числовые настройки YAML | Сохранены как предварительный профиль; обязательна сверка с кафедрой |
| Минимум слов введения/заключения | Порог зависит от типа работы | Рекомендация без штрафа |
| Минимум источников | Порог зависит от типа работы | Рекомендация без штрафа |
| Названия теоретической и практической частей | Определяются по шаблонам заголовков | Нераспознанное название не доказывает отсутствие содержания; рекомендация без штрафа |
| Оценка | Вычитание за каждое сообщение | Вычитание за отдельный критерий; повтор одного нарушения не умножает штраф |
| Защита, плагиат, достоверность источников | Не проверяются | Диагностический балл не является академической оценкой |

Пресеты получили `provenance`, `advisory_rules`, `scoring_policy`. Для подтверждения
профиля нужны программа/кафедра, действующая методичка с датой и точные пункты.
После их проверки обновляются числовые параметры, ссылки и область применения;
лишь затем допустим `department_verified`. Найденный источник сам по себе не
подтверждает весь профиль. Требования другого вуза не подставляются вместо ЗКУ.

## Архитектура и расчёт

Валидаторы производят наблюдения. RuleEngine применяет статус рекомендаций.
ScoringPolicy содержит версию и размеры штрафов; scoring группирует нарушения
по источнику и критерию. Три проверки шрифта объединены; отсутствие библиографии
не штрафуется повторно за отсутствие раздела. Для AI без rule_id совпадение
определяется по нормализованному сообщению: смысловые перефразирования пока могут
оставаться разными замечаниями. Confidence масштабирует только AI-штраф.

Доли штрафов 0.35/0.15/0.05 — настраиваемая диагностическая эвристика,
а не опубликованная шкала ЗКУ. Нужна калибровка на размеченных преподавателями
работах, прежде чем говорить о точности прогнозирования оценки.

CheckResult хранит версию расчёта, статус профиля и расшифровку по категориям.
Итог равен сумме показанных округлённых категорий; при неполном AI его категории
исключаются из числителя и знаменателя. Сумма сырых удержаний ограничивается
максимумом категории. Старые JSON читаются с версией legacy; существующие
результаты не пересчитываются и миграция схемы БД не требуется.

PDF отделён от расчёта. `reports/text.py` отвечает за безопасный текст и проверку
глифов, `fonts.py` — за шрифты, `pdf.py` — за вёрстку. Эмодзи статуса заменены
цветными текстовыми метками. Русские и казахские буквы сохраняются; отсутствующие
глифы обозначаются кодом Unicode. При отсутствии подходящего TTF формирование
явно завершается ошибкой, вместо отправки нечитаемого отчёта. В Docker уже
устанавливается DejaVu; для другого окружения доступен PDF_FONT_PATH.

## Ограничения

OOXML не воспроизводит вёрстку Word: точные страницы, размещение номеров,
титульный лист и сложные формулы требуют отдельной проверки. Полнота детерминированных
проверок пока не выражена отдельным процентом покрытия. Высокий балл означает
отсутствие обнаруженных нарушений выбранного профиля, а не гарантию качества работы.


## Обновление от 27.09.2026

Версия расчёта 3 заменяет описанное выше исключение всех AI-категорий при любом
сбое. Успешный анализ сохраняется по категориям, показывается охват текста.
Максимум результата всегда 100; неполный результат нормируется по доступным
весам и обозначается предварительным. Числовые штрафы остаются эвристикой.
Подробный актуальный алгоритм приведён в ARCHITECTURE.md.
