## Приоритет P1 — исправить до публичного использования

### 1. Чужие результаты доступны без проверки владельца

Места: `app/bot/handlers/document.py:157`, `app/api/routes/checks.py:12`, `app/database/repositories/check_repository.py`.

`_load_check()` получает запись только по check_id. Переданный db_user используется для языка, но не для авторизации. Все кнопки результатов, включая PDF, используют этот метод. В группе другой пользователь может нажать кнопку чужого результата. API при запуске вообще не требует аутентификации и отдаёт findings по последовательному числовому ID. API не включён отдельным сервисом в текущий compose, но становится уязвимым при публикации через uvicorn.

Исправление: запрос результата через связь Check → Document → User с фильтром владельца; отдельно определить права администратора. Для API добавить аутентификацию либо отключить маршрут до её появления. Проверить доступ двумя разными пользователями.

### 2. Docker-сборка включает локальные секреты

Место: `Dockerfile:16`. В корне нет `.dockerignore`, при этом есть локальный `.env`.

`COPY . .` включает `.env`, `.git`, локальные данные и отчёты в образ при обычной сборке из этого каталога. `.gitignore` не управляет Docker build context. Это создаёт риск передачи секретов вместе с образом; факт публикации образа или утечки не установлен.

Исправление: добавить `.dockerignore`, исключить `.env*` с необходимыми исключениями для шаблона, `.git`, `data`, кэши и локальные окружения. Предпочесть явное копирование нужных директорий. Если такие образы уже передавались другим лицам — проверить их состав и при подтверждённом включении секретов заменить ключи.

### 3. Нет ограничений распакованного размера DOCX

Места: `app/security/validation.py:50`, `app/bot/handlers/document.py:53`.

Ограничен размер загруженного ZIP, но не сумма распакованных частей, размер одной части, число элементов или коэффициент сжатия. `testzip()` распаковывает содержимое синхронно прямо в обработчике бота. Маленький сжатый файл может потребовать больших ресурсов и заблокировать обработку остальных сообщений. Последующий python-docx также читает содержимое архива.

Исправление: проверять ZipInfo и лимиты до testzip/разбора, ограничить чтение распакованных данных и перенести тяжёлую проверку из event loop. MIME, расширение и заявленный размер проверять до скачивания; фактический размер продолжать проверять независимо. Отдельно ограничить одновременно выполняемые проверки пользователя.

### 4. Оформление из стилей Word читается неправильно

Места: `app/document/parser.py:194`, `app/document/parser.py:137`.

Читаются непосредственные свойства run/paragraph, без разрешения наследования из стилей, base_style, docDefaults и темы. Отсутствующий прямой alignment превращается в left. В результате правильно оформленный через Normal документ получает ошибки. Определение заголовка также не читает outlineLvl из определения произвольного стиля и его предков.

Исправление: единый механизм вычисления эффективного форматирования с обработкой цепочки наследования и явных сбросов. Проверять одинаковые документы с прямым форматированием и стилями — результат должен совпадать.

### 5. Двойной и точный интервалы ошибочно считаются правильными

Место: `app/rules/validators/spacing.py:17`.

Любой непустой line_spacing_rule без строки MULTIPLE пропускается. Для 2.0 python-docx возвращает DOUBLE, поэтому неправильный двойной интервал получает PASS. EXACTLY также пропускается. Неопределённое значение без проверки наследования тоже считается успешным.

Исправление: сравнивать enum, нормализовать SINGLE/DOUBLE/ONE_POINT_FIVE/MULTIPLE и отдельно обрабатывать EXACTLY/AT_LEAST. Не выдавать PASS, если параметр не удалось проверить.

### 6. Документы без заголовков обходят AI-проверку

Места: `app/document/structure.py:200`, `app/ai/analyzer.py:99`.

Разбиение начинается только от распознанных заголовков. Нет заголовков — нет текста для AI. Текст до первого заголовка также теряется. Анализатор возвращает `([], True)`, и пользователь не видит предупреждения о пропущенной проверке.

Исправление: сохранять текст до первого заголовка отдельным блоком; при отсутствии заголовков анализировать весь основной текст порциями. Хранить объём фактически проверенного текста и сообщать о неполном покрытии.

### 7. Невалидный ответ AI выглядит как успешная проверка

Места: `app/ai/schemas.py:56`, `app/ai/analyzer.py:174`, `app/ai/analyzer.py:219`.

`AIErrorList` допускает `{}` как пустой список ошибок. У IntroductionAnalysis все признаки необязательные с default=False: ответ `{"errors":[]}` превращается в заключение об отсутствии всех элементов введения. ValidationError в парсерах превращается в `[]`, но ai_ok остаётся True.

Исправление: обязательные поля схем; отделить отсутствие ошибок от неуспешного ответа; учитывать ошибки схем в статусе AI. Сохранять успешные результаты отдельных проверок, если другая проверка той же порции текста упала.

### 8. Mock и неизвестный провайдер могут выдавать результат за настоящий AI

Места: `app/ai/provider.py` — MockProvider и build_llm_provider; `app/ai/analyzer.py:159`.

Неизвестное имя провайдера молча переключает систему на mock. Mock всегда возвращает `{"errors":[]}`, но для введения это вызывает ложное предупреждение из пункта 7. В обоих случаях ai_analysis_available=True.

Исправление: неизвестная конфигурация должна завершать запуск понятной ошибкой. Mock разрешать явно в тестах/демо и обозначать пользователю; он не должен влиять на оценку как результат реального анализа.

### 9. Не выполненный AI получает максимальные баллы

Места: `app/analysis/scoring.py:63`, `app/analysis/aggregator.py:27`.

Scoring начинает все категории с максимума и не получает информацию о выполненных проверках. При недоступном AI язык, стиль и содержание сохраняют максимум — в курсовом пресете это 50 баллов. Предупреждение о частичном анализе не исправляет вводящую в заблуждение числовую оценку.

Исправление: категории со статусом «не проверено», отдельный итог по проверенной части с корректным знаменателем либо отсутствие общего балла до завершения обязательных проверок.

### 10. Сбой постановки в очередь оставляет вечную RUNNING-проверку

Места: `app/bot/handlers/document.py:71`, `app/queue.py:34`.

Check создаётся сразу как RUNNING и фиксируется до отправки сообщения и enqueue. Если Redis или отправка progress-сообщения падает, откат middleware уже не отменяет запись. Job отсутствует, проверка остаётся RUNNING, дневной лимит уже расходуется, файл остаётся до очистки.

Исправление: PENDING до фактического старта worker, обработка ошибок enqueue, идемпотентный идентификатор задачи и восстановление зависших записей. Для надёжной доставки между БД и Redis — transactional outbox.

### 11. Отмена worker удаляет файл без завершения статуса проверки

Места: `app/worker.py:145`, `app/worker.py:154`, `app/worker.py:183`.

CancelledError не перехватывается обработчиком Exception, но finally удаляет исходный файл. При timeout/shutdown проверка может остаться RUNNING; повторное выполнение не сможет прочитать документ. В WorkerSettings не задан собственный job_timeout. В установленном arq значение по умолчанию — 300 секунд; для версии из requirements это следует отдельно подтвердить. При множестве порций и повторных LLM-запросах нужно согласовать все таймауты.

Исправление: явная политика отмены/повторов, сохранение документа до окончательного результата, идемпотентное сохранение findings, восстановление статусов после аварий.

## Приоритет P2 — точность, надёжность и эксплуатация

### 12. Ошибка доставки отменяет уже сохранённый результат

Место: `app/worker.py:107`.

Результат фиксируется как COMPLETED до генерации PDF и отправки Telegram. Любая последующая ошибка приводит к `_fail_check()`, превращая успешно выполненную проверку в FAILED. При повторе complete() добавляет findings ещё раз без очистки.

Исправление: независимые состояния анализа, генерации отчёта и доставки. Повторять доставку без повторного анализа; сохранение результата сделать идемпотентным.

### 13. MAX_AI_TOKENS_PER_CHECK не ограничивает реальную стоимость

Места: `app/ai/chunking.py:69`, `app/ai/analyzer.py:97`, `app/ai/analyzer.py:138`.

Бюджет считает исходный текст один раз, хотя каждая порция отправляется трижды: grammar/style/content. Не учтены шаблоны, ответы, повторы и отдельная отправка всего введения без chunking. Фактический usage провайдера не агрегируется. Удаление порций из бюджета не отражается в статусе полноты проверки.

Исправление: резервировать бюджет на каждый запрос, включая выходные токены, учитывать usage и retries, ограничивать введение и показывать покрытие анализа. Семафор сейчас создаётся на одну задачу: общий лимит worker должен учитывать все параллельные документы.

### 14. Часть настроек не применяется

Места: `app/config/settings.py:48`, `app/rules/models.py:32`, `app/rules/models.py:51`, `app/rules/models.py:57`.

Поиск использования показал: max_pages, min_words_introduction, min_words_conclusion, require_page_break_before_top_level, allow_headings_bold объявлены, но не проверяются. Например, дипломный YAML требует разрыв перед разделом, а валидатор его игнорирует.

Исправление: реализовать соответствующие проверки либо убрать неподдерживаемые настройки и обещания. Для страниц явно различать приблизительную оценку и реальное число страниц после layout.

### 15. Проверяется только первая секция Word, текст таблиц не анализируется

Места: `app/document/parser.py:230`, `app/document/parser.py:259`.

Поля, размер и ориентация берутся из `document.sections[0]`. Изменения в следующих секциях проходят незамеченными. Текст берётся из document.paragraphs; содержимое ячеек таблиц не включается в full_text. Документ только с текстом таблицы отклоняется как не содержащий извлекаемого текста.

Исправление: хранить параметры каждой секции; обходить блоки документа в исходном порядке, включая таблицы. Уточнить область правил для титульного листа, таблиц, подписей и библиографии: сейчас body_paragraphs включает любой непустой абзац без заголовочного стиля.

### 16. Дубликаты библиографии с разными номерами не находятся

Место: `app/rules/validators/references.py:78`.

Нормализация не удаляет номер записи. `1. Author...` и `2. Author...` считаются разными источниками. Подсчёт по длинным строкам также способен принять заголовок за источник: казахский «Пайдаланылған әдебиеттер» не исключается текущим шаблоном.

Исправление: исключать заголовок по границе раздела, удалять номер до сравнения, учитывать Word-нумерацию и многоабзацные записи. Проверять цитирования по основному тексту, исключая сам список литературы.

### 17. Дневной лимит и создание пользователя имеют гонки

Места: `app/bot/handlers/document.py:42`, `app/database/repositories/user_repository.py:25`.

Проверка количества и создание новой записи не атомарны. Несколько одновременных загрузок могут пройти один и тот же лимит. Одновременные первые обновления пользователя могут оба пройти get_by_telegram_id и столкнуться на unique telegram_id.

Исправление: атомарное резервирование квоты/блокировка пользователя, UPSERT для пользователей, лимит активных задач. count_checks_today заменить на SQL COUNT вместо загрузки всех строк.

### 18. Изменение ADMIN_IDS не обновляет существующих пользователей

Место: `app/database/repositories/user_repository.py:26`.

Роль назначается только при создании. Удалённый из ADMIN_IDS пользователь остаётся администратором в БД; добавленный существующий пользователь не получает роль.

Исправление: определить единственный источник прав — конфигурация или управляемая БД — и реализовать назначение/отзыв согласно ему.

### 19. Исторические баллы пересчитываются по новым правилам

Место: `app/bot/handlers/document.py:174`.

В БД хранится общий балл, но категории восстанавливаются по текущему YAML. После изменения весов категории и PDF/старый общий балл расходятся. `score=check.score or total` дополнительно подменяет законный нулевой результат. original_text findings, структура и info-count полноценно не сохраняются.

Исправление: сохранять снимок результата и версию/хэш пресета; проверять score через `is not None`. Не пересчитывать историю по изменившимся правилам.

### 20. Сообщения результатов не ограничены по длине

Место: `app/reports/generator.py:58`.

Ограничено число findings, но не размер message/suggestion. Даже несколько длинных ответов AI способны превысить допустимый размер Telegram-сообщения. Нужны разбиение на сообщения/страницы и ограничения размеров AI-полей. `_finding_line()` также не показывает location, из-за чего в списке ошибок бывает непонятно, где исправлять текст.

### 21. PDF и текст findings хранятся без срока удаления

Места: `app/security/files.py:74`, `app/reports/generator.py:122`, `app/main.py:27`.

Очистка затрагивает только `storage_dir/cw_*`. В reports_dir PDF остаются бессрочно, хотя содержат цитаты из документов; для findings в БД нет политики удаления. Это эксплуатационный вопрос хранения данных, а не утверждение о нарушении закона.

Исправление: отдельные сроки хранения исходников, отчётов и результатов, удаление по запросу пользователя, согласованное сообщение о доступности старых PDF.

### 22. Обрезка длинного имени ломает проверку расширения

Места: `app/common/utils.py:33`, `app/bot/handlers/document.py:47`.

sanitize_display_name обрезает всю строку до 120 символов. У длинного корректного имени может исчезнуть `.docx`, после чего валидатор отклонит документ.

Исправление: проверять расширение исходного имени, сохранять suffix при сокращении отображаемого имени.

### 23. Миграции не являются зависимостью запуска сервисов

Место: `docker-compose.yml:41`, `docker-compose.yml:60`.

Bot и worker ждут готовности PostgreSQL/Redis, но не завершения migrate. При старте всех сервисов на пустом томе пользовательские запросы могут попасть в ещё не созданную схему. Документированный ручной порядок запуска может обходить проблему, но compose сам её не предотвращает.

Исправление: зависимость от успешного завершения migrate или отдельная обязательная стадия deployment. Добавить готовность worker/БД в мониторинг: текущий /health всегда возвращает ok.

## Приоритет P3 — качество сопровождения

### 24. Fallback PDF-шрифта неправильно кэшируется

Место: `app/reports/fonts.py:60` и `app/reports/fonts.py:98`.

При отсутствии TTF первый вызов возвращает Helvetica и выставляет `_registered=True`. Следующий возвращает DocumentorSans, который не зарегистрирован. Последующая генерация PDF может упасть. В штатном Docker установлен DejaVu, поэтому проблема касается запасного пути.

Исправление: хранить имя реально выбранного семейства, отдельно проверить повторный вызов при отсутствии TTF.

### 25. Тесты и репозиторий не обеспечивают проверку рабочих сценариев

Существующие 29 тестов в основном проверяют искусственные DOCX с прямым форматированием. Нет тестов изоляции пользователей, worker/очереди, конкурентного лимита, БД/миграций и большинства пограничных сценариев выше. Integration-тесты охватывают только AnalysisPipeline с mock, а не путь Telegram → Redis → worker → БД → доставка.

В Git отслеживаются **103 файла .pyc**. `.gitignore` содержит только `.env`. Генерируемые DOCX и новые кэши загрязняют рабочую копию. `.github`/CI в проекте не обнаружен.
